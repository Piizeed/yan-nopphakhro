# YAN NOPPHAKHRO / ญาณนพเคราะห์

**เว็บไซต์:** https://yan-nopphakhro.onrender.com

ผูกดวงจากวัน เวลา และสถานที่เกิดครบ 77 จังหวัด สมัคร Free เพื่ออ่านรายวัน 3 ครั้งต่อสัปดาห์ และเลือก Pro 29/69 บาทต่อเดือนสำหรับรายละเอียดเพิ่มเติม

[เริ่มใช้งานฟรี](https://yan-nopphakhro.onrender.com/#login) · [รู้จักเว็บ](https://yan-nopphakhro.onrender.com/about.html)

เว็บผูกดวงพร้อมบัญชีสมาชิกและสิทธิ์ Free / Pro 29 / Pro 69 ตรวจสิทธิ์และนับโควตาบนเซิร์ฟเวอร์ เก็บบัญชีใน SQLite ไม่ใช่สมาชิกจำลองใน localStorage

## เปิดใช้งาน

ใช้ Node.js **22.13 ขึ้นไป แนะนำ 24** (ต้องมี `node:sqlite`) บน Windows ดับเบิลคลิก `start-lakhana.cmd` หรือรัน:

```sh
node server.mjs
```

เปิด http://127.0.0.1:3000/#login แล้วสมัครอีเมล/รหัสผ่านอย่างน้อย 10 ตัวอักษร ยังไม่มีระบบส่งอีเมลยืนยันหรือรีเซ็ตรหัสผ่าน ข้อมูลสมาชิกสร้างที่ `data/members.sqlite` เซสชันมีอายุ 7 วัน ปิดแล้วเปิดเซิร์ฟเวอร์ใหม่ข้อมูลสมาชิกยังอยู่ ไม่ต้องติดตั้ง dependency เพื่อรันชุดไฟล์นี้ เพราะเก็บ WASM/ฟอนต์ไว้แล้ว

ข้อมูลเกิดและโปรไฟล์เก็บแยกตามบัญชีในเบราว์เซอร์ ไม่ซิงก์ข้ามอุปกรณ์ ข้อมูล localStorage รุ่นเดิมยังคงอยู่ แต่ไม่โอนเข้าบัญชีใหม่โดยอัตโนมัติ เพื่อไม่ให้บัญชีอื่นเห็นข้อมูลเก่า

## แพ็กเกจ

| แพ็กเกจ | สิทธิ์ |
|---|---|
| Free | ผูกดวง/พื้นดวง รายวันแบบสรุป 3 ครั้งต่อสัปดาห์ |
| Pro 29 บาท/เดือน | รายวันไม่จำกัด รายเดือน เหตุผลจากมุมดาว ตารางดัชนีรายวันทั้งเดือน |
| Pro 69 บาท/เดือน | ทั้งหมดใน Pro 29 เพิ่มไพ่ 3 ใบรายวัน/รายเดือน กราฟจังหวะชีวิต 12 เดือน และแนวทางทำบุญ/ไหว้พระ/ตั้งจิตขอพร |

- Free กด “เปิดบทอ่าน” จึงนับสิทธิ์ นับตามข้อมูลเกิดและวันที่ เปลี่ยนชื่ออย่างเดียวไม่หักเพิ่ม เปิดดวงเดิมวันเดิมซ้ำในสัปดาห์เดียวกันไม่หักซ้ำ รีเซ็ตทุกจันทร์ 00:00 เวลาไทย
- ตรวจโควตาใน transaction ป้องกันคำขอพร้อมกันเกินสิทธิ์ เปลี่ยนแพ็กเกจในเบราว์เซอร์เองไม่ได้
- เริ่มแพ็กเกจเมื่อยืนยันรับเงิน สมัคร 21 ต.ค. ใช้ถึง **21 พ.ย. 23:59:59 เวลาไทย** ระบบเก็บ cutoff แบบ exclusive เป็น 22 พ.ย. 00:00 น. เดือนที่ไม่มีวันที่เดิมใช้วันสุดท้าย เช่น 31 ม.ค. ถึงสิ้นวัน 28/29 ก.พ.
- ต่อแพ็กเกจเดิมก่อนหมดอายุจะต่อจากวันสิ้นสุดเดิม ไม่มีตัดเงินอัตโนมัติ เปลี่ยนระดับระหว่างยังมีสิทธิ์ต้องรอหมดอายุเพื่อไม่ทับสิทธิ์เดิม
- ไพ่เมเจอร์อาร์คานา 22 ใบ สุ่ม 3 ใบไม่ซ้ำ คงชุดตามบัญชี+รายวัน/เดือนที่เลือก ไม่ใช่ผลจากดาราศาสตร์ กราฟเป็นค่าเฉลี่ย 4 หมวดจากดาวจรทุกเดือน ไม่ใช่อายุขัย

## รับชำระเงินและผู้ดูแล

**ค่าเริ่มต้นยังไม่รับเงิน** ไม่มีเลขบัญชีผู้รับ ไม่มี secret และยังไม่ได้ทดสอบกับเงิน/บริการจริง ไม่รับบัตรในรุ่นนี้ ห้ามอ้างว่าเปิดใช้การอนุมัติอัตโนมัติแล้วจนกว่าจะตั้งค่าและทดสอบผู้ให้บริการจริง

1. สมัครบัญชีผู้ดูแลผ่านหน้าเว็บก่อน
2. เจ้าของเครื่องเท่านั้น รัน `node scripts/admin.mjs your-registered-email` เพื่อให้สิทธิ์ผู้ดูแล ไม่มีปุ่มตั้งตัวเองเป็นผู้ดูแลในเว็บ
3. คัดลอก `.env.example` เป็น `.env` ใส่ `PAYMENT_NAME`, `PAYMENT_ACCOUNT`, `PAYMENT_BANK` ตามบัญชีจริง แล้วเริ่มเซิร์ฟเวอร์ใหม่ อย่าใส่รหัสลับในแชตหรือ commit ไฟล์ `.env`
4. `PAYMENT_MODE=manual`: สมาชิกแนบ PNG/JPEG ไม่เกิน 3 MB พร้อมวันเวลา/เลขอ้างอิง ผู้ดูแลเปิด `/#admin` ตรวจยอดเงินจริงและสลิปซ้ำกับธนาคาร แล้วอนุมัติ/ปฏิเสธ สิทธิ์เริ่มเมื่ออนุมัติ การกดซ้ำไม่เพิ่มอายุซ้ำ

### ตัวเชื่อมตรวจสลิปอัตโนมัติ (เตรียมไว้ ยังไม่เปิดใช้)

มี adapter ตาม [EasySlip API v2](https://document.easyslip.com/en/v2/verify/bank/) ไม่ใช่ payment gateway และไม่รับบัตร เจ้าของต้องสมัครบริการ ยืนยันสิทธิ์ใช้บริการกับธุรกิจของตน และผูกบัญชีรับเงินในบริการก่อน แล้วตั้ง:

```dotenv
PAYMENT_MODE=easyslip
EASYSLIP_API_KEY=YOUR_SERVER_SIDE_SECRET
EASYSLIP_RECEIVER_ACCOUNT=FULL_REGISTERED_BANK_ACCOUNT_NUMBER
EASYSLIP_RECEIVER_BANK=THREE_DIGIT_BANK_CODE
```

ตัว worker ทำงานขณะเซิร์ฟเวอร์เปิด ทุก 60 วินาที ลองตรวจสูงสุด 3 ครั้งห่างอย่างน้อย 3 นาที ตั้งเป้าประมาณ 5–10 นาทีในภาวะปกติ แต่ไม่รับประกันเมื่อธนาคาร/API ไม่พร้อมหรือมีคิวมากกว่า 10 รายการ ระบบอ่านคิวจากฐานข้อมูลต่อได้หลังรีสตาร์ต

ยืนยันยอดตรง 29/69 บาท, match บัญชีเต็มและรหัสธนาคาร, วันเวลาไม่เก่าเกิน 24 ชั่วโมงจากการส่ง, สกุลเงินไทย และเลขธุรกรรมไม่เคยเปิดสิทธิ์มาก่อน ข้อมูลจากผู้ใช้ไม่ถือเป็นผลยืนยัน ทดสอบหน่วยด้วย fixture จำลองเท่านั้น ไม่มีการเรียก API จริงในชุดทดสอบ

หากยืนยันไม่ได้ยังเป็น pending พร้อมหมายเหตุ ให้ผู้ดูแลตรวจต่อ ไม่อนุมัติจากการรอครบเวลา ระบบเก็บเลขธุรกรรมที่ตรวจผ่านแบบ unique และเปิดสิทธิ์ใน transaction เดียว ผู้ใช้เห็นคำขอ/สถานะที่หน้าแจ้งโอนและวันเริ่ม/หมดอายุที่หน้าบัญชี รีเฟรชหน้าเพื่อดูสถานะล่าสุด

บัญชีธนาคารส่วนตัวอย่างเดียวไม่ให้ API ตรวจเงินเข้า ต้องเชื่อมบริการตรวจสอบต่างหาก การรับบัตรต้องเลือกผู้ให้บริการที่ยอมรับธุรกิจนี้โดยชัดเจน: [Stripe ระบุธุรกิจดูดวงเป็น prohibited ในไทย](https://stripe.com/legal/restricted-businesses) จึงไม่ได้เชื่อม Stripe

## ข้อมูลและความปลอดภัย

- รหัสผ่านใช้ scrypt+salt; session token สุ่ม 32 bytes เก็บเฉพาะ hash ในฐานข้อมูล Cookie HttpOnly/SameSite=Strict; จำกัดความถี่สมัคร/ล็อกอินต่อ IP และตรวจ origin สำหรับคำขอแก้ไข
- SQLite เก็บอีเมล วันสมัคร วันเริ่ม/หมดอายุ ประวัติใช้สิทธิ์ ไพ่ คำขอชำระเงิน สลิป และประวัติเปิดสิทธิ์ สลิปไม่ได้อยู่ในโฟลเดอร์ public และ API สลิปเต็มอนุญาตเฉพาะผู้ดูแล
- ข้อมูลเกิดส่งให้เซิร์ฟเวอร์เพื่อคำนวณคำอ่าน ไม่ส่ง AI; เมื่อเปิดโหมด EasySlip หน้าแจ้งโอนระบุการส่งสลิปให้บริการนั้นพร้อมความยินยอม
- หน้า privacy ลบได้เฉพาะข้อมูลเกิดในเบราว์เซอร์ การลบบัญชี/ประวัติเงินต้องให้ผู้ดูแลดำเนินการ ยังไม่มีหน้าลบบัญชี/รีเซ็ตรหัสผ่าน/ยืนยันอีเมล
- ไม่มีการยืนยันตัวบุคคล อีเมลหนึ่งบัญชีไม่ได้ป้องกันผู้ใช้สมัครหลายอีเมล เพื่อเปิดสาธารณะควรเพิ่มยืนยันอีเมล ป้องกันบอท การกู้บัญชี และกำหนดระยะเก็บหลักฐาน/ช่องทางช่วยเหลือให้ครบ
- สำรองฐานข้อมูลด้วย SQLite backup หรือหยุดเซิร์ฟเวอร์ก่อนคัดลอกทั้ง `data/` ซึ่งอาจมี WAL ห้ามสำรองเฉพาะไฟล์ .sqlite ระหว่างเขียน ห้ามนำ `data/` หรือ `.env` ขึ้น public/git

## ตรวจสอบ

```sh
node --test
node scripts/browser-smoke.mjs
```

ชุดทดสอบระบบ 20 รายการครอบคลุมเทียบ ephemeris กับ native reference, เวลาไทย, 77 จังหวัด, เดือนอธิกสุรทิน, ล็อกอิน, quota พร้อมกัน, สิทธิ์ Pro/หมดอายุ, สลิป/ผู้รับ/ยอดผิด, อนุมัติซ้ำ และวันหมดอายุสิ้นวันไทย

Browser smoke ต้องมี Playwright และ Chromium หรือใช้ `PLAYWRIGHT_MODULE_PATH` กับ `BROWSER_CHANNEL=msedge` สร้างเซิร์ฟเวอร์และฐานข้อมูลในหน่วยความจำเอง ไม่ต้องเปิดพอร์ต 3000 และไม่สร้างสมาชิกทดสอบในฐานจริง ครอบคลุมสมัคร/ล็อกอิน Free quota, Pro 29, ไพ่/กราฟ Pro 69, แยกโปรไฟล์ข้ามบัญชี และมือถือ 390px ภาพล่าสุด `artifacts/member-*.png`

## Deploy ภายหลัง

รุ่นสมาชิก **ใช้ static hosting อย่างเดียวไม่ได้** ต้องมี Node 22.13+/24, disk ถาวรสำหรับ SQLite และ process ทำงานต่อเนื่อง ใช้หนึ่ง instance ก่อน ปรับ `HOST=0.0.0.0`, `PORT` ตามโฮสต์ วางหลัง HTTPS reverse proxy และตั้ง `COOKIE_SECURE=1` เก็บ secrets ใน env ของโฮสต์ ห้ามเปิดฐานข้อมูลผ่านเว็บ ตั้งระบบ backup/monitoring และจำกัดขนาดคำขอ 4.2 MB พร้อม rate limit ที่ reverse proxy (ตัว rate limit ในแอปเป็นราย IP ที่เชื่อมต่อโดยตรง)

ยังไม่ได้ deploy สาธารณะหรือรับเงินจริง ก่อนเปิดบริการต้องเตรียมบัญชีรับเงิน/ผู้ให้บริการที่รองรับธุรกิจนี้ ทดสอบธุรกรรมจริงและกรณีคืนเงิน ใส่ข้อมูลผู้ประกอบการ/ติดต่อ/เงื่อนไขบริการ และตรวจสิทธิ์เผยแพร่ซอฟต์แวร์
